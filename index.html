Motion tokens

One shared set of motion tokens for iOS and Android. Page navigation, sheets, dialogs and full-screen modals differ by platform, because that’s where iOS and Android users expect different movement. Bounce is only used for a confirmed success, never when money leaves. Press uses scale-sm on both platforms: a deliberate Bolt choice, because natively iOS dims and Android ripples, and one press keeps the webview consistent.

These tokens are part of the Clay design system. In text, they’re written without the --motion- prefix, and sizes always refer to Clay dimension tokens, for example dimension-100.

Playground

Pick a duration and a curve, then tap the card. Springs have their own timing, so the duration is ignored when one is selected. Each spring shows what it’s made for: spring-smooth settles a move, spring-snappy flips a toggle, and spring-bouncy pops in. Copy CSS gives you the snippet.

Duration

Five steps, 100 ms apart. The size of the change decides the step, not the type of component. Exits use the next shorter step.

Easing

Things arriving slow down, things leaving speed up, and things moving on screen use ease-standard. ease-standard is also the default curve for anything without a more specific rule. ease-ios is only used inside the iOS platform tokens.

Springs

Each spring is defined by a duration and a bounce. In CSS they’re sampled into linear(), and the CSS duration is how long the spring takes to settle. Exits use spring-snappy, the shorter spring.

Distance, scale and fade

Shared values that combine with durations and curves. Distances use Clay dimension tokens, so motion adds no new sizes. Shared values are named by size (sm, md, lg); platform tokens are named by surface (nav, sheet, dialog, modal). Two shared tokens have no example here: --motion-scrim uses the Clay special/scrim colour, and --motion-spinner-delay (duration-sm) is how long to wait before showing a spinner.

Guardrails

These apply to every animation. If two conflict, the lower number wins.

Platform-forked tokens

These are the only tokens that differ by platform. Android values are the default, and data-platform="ios" on the root element switches to iOS. Each one sets travel, scale and easing, not just duration. Every scrim uses the Clay special/scrim colour. Switch platforms in the phone to compare, and drag the sheet: iOS stretches a little, Android follows the finger exactly.

Pages and sheets

  • --motion-nav-enter
    iOS: duration-xl with ease-ios. The new page slides in from the side and the old page moves back by nav-parallax (30%). Android: duration-lg with ease-standard. Both pages shift by distance-lg while they cross-fade, over the same duration.
  • --motion-nav-exit
    iOS: duration-lg with ease-ios. Android: duration-md with ease-standard. If the page is still moving, reverse from where it is and use only the time needed for the distance left.
  • --motion-sheet-enter / --motion-sheet-exit
    Sheets rise from the bottom on both platforms. iOS: duration-xl in and duration-lg out, with ease-ios. The page behind scales to 0.93 and the sheet stretches a little when dragged. Android: duration-lg with ease-enter in and duration-md with ease-exit out. The page behind stays the same size and the sheet follows the finger exactly. Both use the Clay special/scrim colour and, on release, settle with spring-smooth at the finger’s speed.
  • --motion-dialog-enter / --motion-dialog-exit
    A centred alert that fades and scales without sliding. iOS: starts at 0.97, duration-sm in and duration-xs out, with ease-ios. Android: starts at 0.92, duration-md with ease-enter in and duration-sm with ease-exit out. On both, the fade and the scrim use dialog-fade-enter (spring-smooth) and dialog-fade-exit (spring-snappy), so the dim and the dialog move together. A dialog over a sheet leaves the sheet still and uses one scrim.
  • --motion-modal-enter / --motion-modal-exit
    A full-screen task, not a step deeper into the app. iOS: covers the screen from the bottom, duration-xl in and duration-lg out, with ease-ios. Nothing moves or scales behind it. Android: scales up from 0.92 over a scrim, duration-lg with ease-enter in and duration-md with ease-exit out. The fade and the scrim use modal-fade-enter (spring-smooth) and modal-fade-exit (spring-snappy), like the dialog.

Delight

Delight is for moments with real emotion. Cashback and the success page each get one bounce because something good is confirmed. Payment confirms calmly because money is leaving, and Activity, card lock and wrong PIN show where motion stays quiet.

Edge cases

Situations where following the tables literally gives the wrong result. Several come from running inside the native app’s webview.

Reduce Motion

Swap motion, don’t remove it. iOS replaces slides with cross-fades when Reduce Motion is on, and we do the same. On Android, check that the Remove animations setting reaches the webview; if it doesn’t, the native app has to pass it in. Turn on the preview at the top to see every example this way.

Code

Load motion-tokens.css after Clay’s tokens so the dimension values resolve, and put motion.ts next to your Motion components. Call applyPlatformAttribute() once on the client when the app starts, and read platform recipes with getRecipes() after hydration. Use recipes from motionSystem (press, fade, sheet, dialog, modal), not loose durations. The snippets below are generated from that object so they cannot drift from the demos.
